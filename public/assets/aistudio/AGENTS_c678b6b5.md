# دستورالعمل ایجنت CPAI

## مأموریت
بازطراحی UI/UX سامانه موجود، نه بازنویسی آن. رابط فارسی RTL، آرام، خوانا و مناسب یادگیری مدیران. اولویت ماژول‌های آموزشی شلوغ است.

## قوانین غیرقابل نقض
- ابتدا دستورالعمل‌های موجود repo (AGENTS.md، README، CONTRIBUTING و مشابه) را بخوان؛ آن‌ها را جایگزین نکن. در تعارض، توقف و گزارش.
- git status، branch، remote و تغییرات محلی را بررسی کن. تغییرات کاربر را حذف، stash یا overwrite نکن. از reset --hard، force push و پاک کردن فایل‌های نامرتبط استفاده نکن.
- از شاخه پایه تأییدشده و به‌روز، برنچ feature/ui-ux-redesign بساز. اگر موجود است یا working tree کثیف است، قبل از تغییر وضعیت گزارش بده. main و production را تغییر نده.
- هیچ merge، deploy، migration، تغییر secrets یا انتشار خودکار بدون تأیید صریح. Push و PR نیز فقط طبق مجوز کاربر و پس از بررسی diff.
- محتوا، ترتیب ماژول‌ها، شناسه‌ها، پیشرفت، دسترسی، نقش‌ها، API contract و رفتار سندباکس و AI را حفظ کن. نمونه‌های Figma را جایگزین داده واقعی نکن.
- از stack، package manager، routing و component library موجود استفاده کن. وابستگی جدید فقط با دلیل و تأیید در صورت ریسک.
- کلیدها، توکن‌ها و داده شخصی را وارد کد، لاگ یا گزارش نکن. کنترل دسترسی سمت سرور را تضعیف نکن.
- هر تغییر کوچک، قابل تست و قابل بازگشت باشد. هیچ mock را به عنوان قابلیت واقعی تحویل نده.

## روش تصمیم‌گیری
منبع حقیقت عملکرد و محتوا: سورس موجود. منبع حقیقت بصری: فریم‌های Figma. منبع اولویت و محدودیت: PRD و این دستورالعمل. اگر تناقض وجود دارد، حفظ رفتار فعلی مقدم است؛ اختلاف را ثبت کن. اگر قابلیت طراحی‌شده در سورس وجود ندارد، آن را پیشنهاد مرحله بعد ثبت کن.

## خروجی هر مرحله
فایل‌های تغییرکرده، دلیل تغییر، دستور و نتیجه واقعی تست، تصاویر قبل/بعد در صورت امکان، ریسک‌های باقی‌مانده، وضعیت git و گام بعد. تست اجرا نشده را صریح بنویس. ادعای موفقیت بدون شاهد ممنوع.
